==================================================
1. PRODUCT GOAL
==================================================

The controller needs room for richer interactions without making every touch target
tiny or relying on invisible global swipe gestures.

Introduce three conceptual screens:

  NOW PLAYING
  GROUPING
  PLAYGROUND

Initially:

NOW PLAYING
  existing useful playback UI

GROUPING
  placeholder / shell only in this milestone

PLAYGROUND
  dedicated area for interaction experiments

Rooms and Queue already exist as views reached from Now Playing (room header, Queue
button, Back). They remain SUB-VIEWS of Now Playing, not top-level screens:

  top-level:  Now Playing  ->  Grouping  ->  Playground  ->  Now Playing
  sub-views:  Now Playing { Rooms, Queue }

The navigation button cycles only top-level screens. Pressing it while a sub-view is
open moves to the next top-level screen and discards the sub-view; arriving back at Now
Playing later shows Now Playing itself, never a remembered sub-view.

Do not implement grouping functionality yet.

==================================================
2. HARDWARE-BUTTON SCREEN NAVIGATION
==================================================

Use an appropriate existing physical hardware button to cycle screens.

Desired behavior:

  Now Playing
      ->
  Grouping
      ->
  Playground
      ->
  Now Playing

Use ONE explicit short-press action.

The button is BOOT (GPIO0). Today Waveshare.cpp only samples it as local activity
(digitalRead(0) == LOW) with no edge detection or debounce, and it is the deep-sleep
wake source, so it is still held low while the device boots after a wake.

Required mechanics (reuse the adapter implementation from 0-lvgl if it exists):

- action on release (edge-triggered), not on press
- debounce >= 30 ms
- a hold longer than 1 s performs no action (no long-press semantics)
- the press that woke or booted the device is consumed: require a release before the
  first navigation press is accepted (Stick.cpp's releaseAfterBoot is the same pattern;
  Waveshare.cpp's `held` does this for touch)
- press/hold still counts as local activity exactly as today

PWR stays unused: it is PMIC-owned, sensed through the expander, and a long press powers
the board off.

Expose the same action over USB as `ui-nav next` (todo/0-device-tooling.md) so agents
can drive navigation without a finger. USB navigation does not count as local activity.

Do not use:

- global swipe navigation
- edge gestures
- hidden touch zones
- double/triple click navigation
- long-press navigation

Touch should remain local to the currently visible screen.

==================================================
3. SCREEN NAVIGATION STATE
==================================================

Model active screen separately from Sonos/application state.

Conceptually:

  ScreenNavigationState
    activeScreen

This is UI navigation state.

It is NOT:

- ObservedState
- PendingState
- Sonos state
- device config
- room state

Changing screens must never itself mutate Sonos.

Do not persist active screen across reboot/sleep.

Fresh boot starts at Now Playing.

Room change: WaveshareUi::update currently forces the Now Playing sub-view and cancels
any touch whenever the observed target changes. Keep that for sub-views, but a room
change must NOT change the top-level screen: a user on Playground stays on Playground.
Grouping is a placeholder and may do whatever is simplest.

==================================================
4. SCREEN-LOCAL INTERACTION
==================================================

Each screen may have ephemeral local interaction state.

When leaving a screen:

- cancel/release active touch interactions owned by that screen
- do not cancel already accepted Sonos mutations
- do not alter observed Sonos state
- do not alter grouping
- do not alter selected room

A touch started on one screen must never complete against controls on another screen.

A volume or seek preview active on Now Playing when the button is pressed is cancelled
and submits nothing.

==================================================
5. MINIMAL SCREEN INTERFACE
==================================================

Introduce only the smallest abstraction justified by multiple screens.

Conceptually something like:

  Screen
    onEnter()
    onLeave()
    handleTouch(...)
    render(...)

and:

  ScreenManager
    active screen
    next()

Exact names/design are implementation choices.

[LVGL] Each top-level screen is one LVGL screen object created once (at boot or lazily)
and switched with lv_screen_load; onEnter/onLeave are thin C++ hooks around the load.
Before switching, cancel the active touch (lv_indev_wait_release or lv_indev_reset on
the indev) so a press started on the old screen cannot release on the new one. Now
Playing's Rooms/Queue sub-views may be LVGL containers toggled inside the Now Playing
screen or separate LVGL screens; choose the smaller change. No custom hit-testing.

[HAND-ROLLED] Split WaveshareUi into a ScreenManager that owns activeScreen and the
shared gesture state (contact, firstX/firstY, cancelled, previews) plus per-screen
state/hit tables for NowPlaying (including its Rooms/Queue sub-views), Grouping, and
Playground. WaveshareDrawing gains one draw function per top-level screen. Keep the
existing 16 px cancel threshold and release-to-submit semantics.

Do not create:

- generic widget hierarchy
- virtual DOM
- animation framework
- layout engine
- navigation stack
- router

We need three screens and explicit lifecycle/ownership, not a UI framework.

9. TOUCH OWNERSHIP
==================================================

Touch dispatch must go only to the active screen.

No screen should independently poll global touch state and accidentally react while
hidden.

A screen transition must clear/cancel active touch ownership.

[LVGL] LVGL already dispatches only to the loaded screen; the required proof is that a
screen switch during a press cannot complete on the new screen (section 5).

[HAND-ROLLED] Only the ScreenManager receives touch samples and forwards them to the
active screen; screens never read the adapter directly.

Preserve current touch calibration in the hardware adapter.
